Reports

Reports waiting on your signature. Each one is generated here, for this patient, and handed to the signing service as the document itself.

There is no template behind these. A twenty-five or thirty page report is different for every patient, so this records system renders the PDF, names the widgets in the signature block on the last page (clinician_signature, clinician_date, and cosigner_* where a second clinician signs), and uploads it over the same API key it uses for everything else. The service checks it, reads the field positions off those names, removes every widget, stores what we sent and the bytes it will actually show, and records both hashes. From there it is an ordinary electronic envelope.
